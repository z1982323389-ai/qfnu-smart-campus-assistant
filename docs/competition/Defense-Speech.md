# 曲智通答辩讲稿

各位评委老师好，我们的作品是曲智通，英文名 QFNU Smart Campus Assistant。它是面向曲阜师范大学师生的 AI 校园事务咨询与信息核验助手。

我们做这个项目的出发点很简单。校园里并不缺信息，学校官网、学院通知、图书馆页面和各类公开文件都在持续发布内容。但当学生真的要办一件事时，他需要的不是再看一堆链接，而是知道这件事适不适合我、应该先做什么、准备哪些材料、联系哪个部门、有没有截止时间。

所以曲智通的定位不是聊天机器人，也不是校园百科。它的目标是把公开资料转化为办事前的核验建议和咨询入口。

首版我们选择了八个高频场景：校园办事咨询、新生指南、奖助学金、教务政策、图书馆服务、校园通知解读、部门联系方式和 FAQ。这些场景都有共同特点：资料大多可以从公开页面获得，师生经常需要，且不需要接入学校内部系统就可以完成有价值的演示。

我们非常明确地划定了产品边界。曲智通不查询成绩，不查询课表，不查询校园卡余额，不查询宿舍电费，也不处理个人审批进度。因为这些能力依赖学校内部系统和身份认证，学生团队在没有授权的情况下不应该模拟或承诺这类功能。我们认为这个边界本身也是项目可落地的重要前提。

在产品体验上，用户可以直接在 AI 聊天页提问，例如“学生证丢了怎么办”。系统不会只返回一段泛泛的回答，而是按照咨询结构输出：公开资料摘要、核验步骤、材料提示、咨询渠道、注意事项、来源引用和相关推荐。如果用户询问成绩或课表等内部数据，系统会进入拒答路径，并建议用户通过官方系统查询。

技术上，我们使用 Next.js、TypeScript、TailwindCSS 和 shadcn/ui 构建前端与服务端 Route Handler。AI 调用只在服务端完成，API Key 不会出现在前端。系统内部有统一 API 响应、错误处理、限流、AI 服务适配层和校园 Workflow。

曲智通的 AI Workflow 包括输入清洗、意图识别、知识库检索、结构化回答、来源引用、相关推荐和拒答机制。这个 Workflow 的作用是约束 AI，让它按照校园事务咨询逻辑工作，而不是自由发挥。

知识库方面，我们采用轻量文件化方案，支持 Markdown、PDF、Word 和 TXT。每条资料都会有分类、标签、适用对象、来源、版本、更新时间和状态。当前系统已经实现轻量检索 API，AI 回答可以引用知识库命中的资料。

为了证明项目可持续维护，我们还设计了后台配置页面。后台可以展示知识库条目、状态、版本、分类、标签和 Prompt 模板。后续如果学校公开资料更新，维护者可以扩充知识库，而不是修改代码。

这个项目的创新点不在于“用了 AI”这件事，而在于把 AI 放进校园公开信息核验的具体场景里。它轻量，不依赖内部系统；它可信，回答基于知识库和来源；它可维护，资料和 Prompt 可以持续更新；它可演示，已经具备首页、聊天、知识库、办事大厅和后台配置雏形。

后续我们计划继续补充曲阜师范大学公开资料，完善 Coze Workflow，增强知识库导入和后台编辑能力。如果未来获得学校正式授权，再评估与内部系统的安全对接。

以上就是我们的作品曲智通，谢谢各位老师。
