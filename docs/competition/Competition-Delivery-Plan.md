# 曲智通比赛交付方案

## 比赛定位

曲智通应以“轻量可落地的 AI 校园办事平台”参赛，而不是以“大模型聊天应用”参赛。评委更可能关注项目是否真实解决校园问题、是否符合学校场景、是否能够上线维护、是否避开权限和合规风险。

项目的核心叙事建议为：学校已有官网、通知和系统，但信息分散、语言正式、检索成本高。曲智通用 AI 把公开资料转化为办事流程、材料清单、通知摘要和部门引导，让师生更快完成校园事务前的准备。

## 作品简介

曲智通是面向曲阜师范大学师生的 AI 校园办事与信息服务平台。平台基于学校公开资料、知识库和 AI Workflow，支持校园办事咨询、新生指南、奖助学金、教务政策、图书馆服务、校园通知解读、部门联系方式和 FAQ。系统不接入学校内部数据库，不查询个人成绩、课表、校园卡余额等敏感信息，强调可信来源、流程化回答和可持续维护。

## 创新点

| 创新点 | 说明 |
|---|---|
| 从聊天转向办事 | 回答不止是文本，而是事项说明、步骤、材料、部门和下一步建议 |
| 公开资料可落地 | 不依赖内部系统权限，符合高校学生团队真实开发条件 |
| Workflow 控制回答 | 通过意图识别、知识库检索、回答生成、相关推荐和拒答机制降低幻觉 |
| 通知解读场景 | 将校园通知转为摘要、关键时间、影响对象和需要行动 |
| 可维护知识库 | 支持分类、标签、引用、版本和后台配置，便于后续扩展 |
| 比赛友好演示 | 首页、办事大厅、AI 聊天和后台配置形成完整产品闭环 |

## 项目亮点

曲智通的亮点不是调用了 AI，而是把 AI 放进校园办事流程中。用户问“奖学金需要准备什么”时，系统应输出适用对象、申请步骤、材料说明、注意事项和来源；用户粘贴通知时，系统应提炼影响对象、关键时间和需要完成的动作。

产品设计上，曲智通采用现代 Web 应用体验，兼顾 PC、Pad 和 Mobile，并支持 Dark Mode、Loading、Toast、404、500 和 Error Boundary。工程设计上，API Key 只在服务端使用，AI 接口具备统一异常、限流和重试机制。

## 技术路线

```text
Next.js + TypeScript + TailwindCSS + shadcn/ui
  |
  v
Route Handler API
  |
  v
AI Service + Coze API
  |
  v
Intent Recognition + Knowledge Retrieval + Answer Generation
  |
  v
Markdown / PDF / Word / TXT Knowledge Base
  |
  v
Vercel Deployment
```

这条技术路线轻量、现代、可部署，适合高校创新开发比赛。与依赖学校内部系统的方案相比，它更容易在短时间内完成并公开演示。

## 应用价值

| 对象 | 价值 |
|---|---|
| 学生 | 更快理解政策和流程，减少反复查找通知和询问他人的成本 |
| 新生 | 快速熟悉校园办事入口和常用服务 |
| 辅导员 | 降低重复答疑压力，统一政策解释口径 |
| 教师 | 快速获取公开部门信息、通知摘要和学生事务说明 |
| 学校 | 以低成本方式提升公开信息服务体验 |

## 推广价值

曲智通的模式可以扩展到学院、部门和其他高校。只要更换知识库资料和 Prompt 约束，就可以迁移到不同校园场景。产品不强依赖内部系统，部署成本较低，适合先以公开信息服务上线，再逐步申请官方数据授权。

## 答辩 PPT 规划

建议 PPT 控制在 10 到 12 页：

| 页码 | 标题 | 内容 |
|---|---|---|
| 1 | 项目封面 | 曲智通、团队、比赛主题 |
| 2 | 校园问题 | 信息分散、政策难懂、流程不清、重复答疑 |
| 3 | 产品定位 | AI 校园办事与信息服务平台 |
| 4 | 用户与场景 | 学生、新生、教师、辅导员 |
| 5 | 核心功能 | 八个首版模块 |
| 6 | 产品演示路径 | 首页、办事大厅、AI 聊天、通知解读、后台 |
| 7 | AI Workflow | 意图识别、检索、生成、引用、拒答 |
| 8 | 技术架构 | Next.js、Route Handler、Coze API、知识库、Vercel |
| 9 | 创新与优势 | 可落地、可信来源、办事流程化、可维护 |
| 10 | 安全与边界 | 不接入内部系统、不处理个人隐私、密钥保护 |
| 11 | 应用价值 | 面向师生和学校管理的价值 |
| 12 | Roadmap | 后续扩展与推广 |

## 答辩讲稿规划

讲稿建议采用三段式。第一段说明为什么需要曲智通：校园公开信息很多，但用户办事时需要的是具体流程和下一步。第二段说明曲智通如何工作：基于知识库和 Workflow，把问题转为可信、结构化、带来源的办事答案。第三段说明为什么能落地：不依赖内部系统，技术栈轻量，部署简单，后台可维护。

答辩时不要把重点放在“我们用了大模型”。更好的表述是“我们把大模型约束在校园公开资料和办事流程中，让它回答得可信、可追溯、能帮用户行动”。

## 演示脚本规划

建议准备 5 个演示场景：

| 场景 | 演示内容 | 目的 |
|---|---|---|
| 首页进入 | 展示产品定位、热门办事、视觉质感 | 建立第一印象 |
| 学生证补办 | 提问后生成流程、材料、部门、来源 | 展示办事能力 |
| 新生指南 | 从新生入口进入并追问 | 展示多轮对话 |
| 通知解读 | 粘贴校园通知并生成摘要 | 展示 AI 理解能力 |
| 后台配置 | 展示知识库条目、分类、版本 | 展示可持续维护 |

每个场景都应准备稳定问题和备用答案，避免现场网络或模型波动影响演示。

## 作品说明书规划

作品说明书建议包含：项目背景、需求分析、产品定位、功能介绍、系统架构、AI Workflow、知识库设计、安全与隐私、部署说明、使用说明、创新点、应用价值、Roadmap 和团队分工。

说明书应保持真实，不夸大未实现能力。尤其要明确不查询成绩、课表、校园卡余额、电费等内部系统数据，这反而能体现项目对合规和落地的清醒判断。

## 部署说明规划

部署文档应覆盖本地运行和 Vercel 部署。需要说明环境变量配置、Coze API Key 设置、知识库资料位置、构建命令、常见错误和备用演示方式。比赛提交前应保存线上地址、演示账号或后台访问方式、关键页面截图。

## 评委视角判断

如果我是高校 AI 应用创新大赛评委，我会重点看五件事：是否解决真实校园问题，是否有完整产品形态，是否能现场稳定演示，是否避开数据权限风险，是否有持续维护可能。曲智通当前方案在这五点上具备较强竞争力，但前提是首版必须收敛功能，把核心链路做稳。

## 阶段一结论

比赛交付应围绕“可信、轻量、可落地、可演示”展开。后续开发中，任何会拖慢核心链路的功能都应延后；任何能增强评委理解的材料，如 Workflow 图、知识库来源、通知解读演示、后台维护界面，都应优先完成。
