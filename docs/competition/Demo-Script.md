# 曲智通演示脚本

## 演示目标

演示需要让评委在 5 到 8 分钟内理解三件事：曲智通面向真实校园咨询场景，项目不依赖内部系统也能完成演示闭环，当前版本已具备前台、AI、知识库和后台配置雏形。

## 演示路线

推荐路线：

```text
首页 → AI 聊天 → 知识库检索 → 办事大厅 → 后台配置 → 总结
```

## 场景一：首页

操作：

1. 打开首页。
2. 展示标题“AI 校园办事平台”。
3. 说明项目不是聊天机器人，而是校园事务办理前的智能引导入口。
4. 展示八个首版模块和 AI Workflow。

讲解：

曲智通面向曲阜师范大学师生，基于公开资料和知识库，把政策、通知和办事说明转化为查询建议、材料提示和咨询渠道。项目不接入内部系统，避免权限和隐私风险。

## 场景二：AI 聊天

操作：

1. 进入 `/chat`。
2. 输入“学生证丢了怎么办？”。
3. 展示系统返回的结构化回答。
4. 指出核验步骤、材料提示、咨询渠道、来源引用和边界提醒。

讲解：

传统聊天机器人容易输出长段文字。曲智通把回答整理成咨询结构，让用户知道下一步应核验什么、去哪里看原通知。命中知识库时，系统会展示来源和更新时间。

备用问题：

- 奖学金需要哪些材料
- 新生报到要注意什么
- 图书馆电子资源怎么使用

## 场景三：拒答边界

操作：

1. 在聊天页输入“帮我查一下成绩”。
2. 展示系统拒答。

讲解：

项目明确不接入教务系统，不查询个人成绩、课表、校园卡余额等内部数据。这个边界不是能力不足，而是对比赛原型合规性和数据安全的约束。

## 场景四：知识库检索

操作：

1. 进入 `/knowledge`。
2. 搜索“学生证补办”。
3. 展示命中的知识条目、标签、来源和更新时间。
4. 切换分类，例如“奖助学金”或“图书馆”。

讲解：

AI 回答的可信度来自知识库。每条资料都有分类、标签、来源、版本和更新时间。后续可以继续补充学校公开资料，也可以升级为向量检索。

## 场景五：办事大厅

操作：

1. 进入 `/services`。
2. 展示八个核心模块。
3. 展示每个模块的示例问题和回答结构。

讲解：

办事大厅证明曲智通不是单一对话页，而是围绕校园事务组织的产品平台。用户既可以直接提问，也可以按场景进入。

## 场景六：后台配置

操作：

1. 进入 `/admin`。
2. 展示知识库条目列表、启用状态、版本、分类和标签。
3. 展示 Prompt 模板和维护指标。

讲解：

后台配置体现后续可维护思路。学校通知和政策会变化，项目需要能更新资料、管理来源和调整 Prompt，而不是只做一次性页面展示。

## 收尾总结

曲智通首版坚持三个原则：场景真实、边界清晰、轻量可演示。当前项目已完成前台页面、AI API、知识库检索、后台配置雏形和比赛材料基础，后续可以继续扩充公开资料，并在获得正式授权后再评估更多能力。
