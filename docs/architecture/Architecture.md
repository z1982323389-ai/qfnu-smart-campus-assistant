# 曲智通系统架构方案

## 架构目标

系统架构围绕轻量部署、资料可信、前后端边界清晰和后续维护方便来设计。首版不接入学校内部系统，因此架构重点不是复杂数据集成，而是公开资料知识库、AI Workflow、统一 API 封装、错误处理和可部署性。

推荐技术栈保持用户指定方案：Next.js 最新稳定版、TypeScript、TailwindCSS、shadcn/ui、Framer Motion、React Hook Form、Zod、Node.js Route Handler、Coze API、Vercel 部署。

## 总体架构

```text
用户浏览器
  |
  | 访问页面、提交问题、查看引用
  v
Next.js App Router
  |
  | 页面渲染、表单校验、状态管理、错误边界
  v
Route Handler API
  |
  | 鉴权预留、限流、参数校验、日志、异常包装
  v
AI Service Layer
  |
  | Prompt 组装、Coze API 调用、重试、结果规整
  v
Workflow Layer
  |
  | 意图识别、知识库检索、回答生成、相关推荐、拒答
  v
Knowledge Base
  |
  | Markdown / PDF / Word / TXT / 元数据 / 版本 / 来源
```

## 前端架构

前端采用 App Router 组织页面。页面层只负责展示和交互，不直接调用 Coze API，也不持有任何密钥。复杂 UI 被拆成页面组件、业务组件和基础组件三层。

| 层级 | 职责 | 示例 |
|---|---|---|
| 页面层 | 路由、页面布局、元信息 | 首页、AI 聊天、办事大厅、后台配置 |
| 业务组件 | 业务卡片和交互模块 | 办事流程卡、引用来源卡、推荐问题、知识库条目表单 |
| 基础组件 | 通用 UI 能力 | Button、Dialog、Toast、Empty、Loading、ErrorState |
| 状态与表单 | 表单校验、输入状态、错误提示 | React Hook Form、Zod |
| 动效 | 进入动画、卡片过渡、加载反馈 | Framer Motion |

UI 风格应接近 Apple、Linear、Notion 和 ChatGPT 的交集：大留白、低噪声、清晰层级、柔和动效、深浅色一致性。比赛演示时，首页和 AI 聊天页最能影响第一印象，应优先打磨。

## 后端架构

后端使用 Next.js Route Handler。所有外部 API 调用都必须经过服务端，前端只访问本项目 API。每个 API 需要统一返回结构，便于前端处理成功、失败、加载和重试。

建议统一响应格式：

```text
{
  success: boolean,
  data?: object,
  error?: {
    code: string,
    message: string,
    detail?: string
  },
  meta?: {
    requestId: string,
    timestamp: string
  }
}
```

首版 API 建议包括：

| API | 用途 | 说明 |
|---|---|---|
| `/api/ai/chat` | AI 问答 | 接收用户问题，返回结构化答案、引用、推荐问题 |
| `/api/knowledge/search` | 知识库检索 | 按关键词、分类、标签检索知识条目 |
| `/api/knowledge/items` | 知识库管理 | 后台新增、编辑、启用、停用知识条目 |
| `/api/logs` | 轻量日志 | 记录请求 ID、模块、错误类型、耗时 |
| `/api/health` | 健康检查 | 用于部署后检查服务状态 |

## AI Workflow

AI Workflow 是项目的核心竞争力。它需要让模型按校园事务咨询逻辑工作，而不是直接自由回答。

```text
用户问题
  |
  v
输入清洗
  |
  v
意图识别
  |
  |-- 校园办事咨询
  |-- 新生指南
  |-- 奖助学金
  |-- 教务政策
  |-- 图书馆服务
  |-- 通知解读
  |-- 部门联系方式
  |-- FAQ
  |-- 超出范围
  v
知识库检索
  |
  |-- 有可信资料
  |       v
  |   回答生成
  |       v
  |   来源引用
  |       v
  |   相关推荐
  |
  |-- 无可信资料
          v
      拒答与人工引导
```

### 意图识别

意图识别需要输出结构化结果，包括用户问题所属模块、是否需要检索知识库、是否涉及个人隐私或内部系统、是否需要拒答、是否需要追问。示例意图包括“办事流程咨询”“政策解释”“通知摘要”“联系方式查询”“新生指南”“无法回答”。

### 知识库查询

知识库查询先按分类和标签筛选，再按关键词与语义相似度检索。首版可从轻量实现开始：文件元数据 + 文本切片 + 本地索引或服务端检索封装。后续如果接入向量数据库，也不影响上层 API。

### 回答生成

回答生成必须遵循固定结构，避免长段落堆砌。校园事务咨询类回答建议包含：摘要、适用对象、核验步骤、材料提示、咨询渠道、注意事项、来源、你还可以问。

通知解读类回答建议包含：一句话摘要、影响对象、关键时间、需要行动、材料清单、风险提醒、来源。

### 相关推荐

相关推荐根据意图和命中的知识库标签生成。比如用户问奖学金，推荐“困难认定怎么申请”“奖学金材料有哪些”“助学贷款在哪里办理”。推荐问题应来自知识库标签和 FAQ，不应完全由模型自由发散。

### 拒答机制

以下情况必须拒答或引导至官方渠道：查询成绩、查询课表、查询校园卡余额、查询电费、查询个人奖学金结果、涉及个人隐私、涉及内部审批状态、知识库没有可信来源。拒答文案应友好，说明原因，并提供可公开查询的替代路径。

## Prompt 设计

系统 Prompt 应强调四条规则。第一，只基于已检索资料回答校园事务问题。第二，无法确认时说明不确定，而不是猜测。第三，涉及内部系统和个人数据时拒答。第四，输出结构化答案并附来源。

建议将 Prompt 拆成多个模板：

| 模板 | 用途 |
|---|---|
| `intent-classifier` | 判断用户意图和风险 |
| `knowledge-answer` | 基于知识库生成校园办事答案 |
| `notice-summary` | 解读校园通知 |
| `recommendation` | 生成相关推荐问题 |
| `refusal` | 生成拒答和人工引导 |

## 知识库设计

知识库必须支持 Markdown、PDF、Word、TXT。首版建议先将资料转换为结构化文本，保留原文件名、来源链接、发布时间、更新时间和版本号。

建议目录：

```text
knowledge-base/
  campus-services/
  freshman-guide/
  scholarships/
  academic-affairs/
  library/
  notices/
  departments/
  faq/
```

知识条目元数据：

| 字段 | 说明 |
|---|---|
| `id` | 知识条目唯一标识 |
| `title` | 标题 |
| `category` | 分类 |
| `tags` | 标签 |
| `sourceType` | Markdown、PDF、Word、TXT、网页 |
| `sourceName` | 来源名称 |
| `sourceUrl` | 公开来源链接，可为空 |
| `campus` | 曲阜校区、日照校区、全校 |
| `audience` | 本科生、研究生、教师、新生、辅导员 |
| `version` | 版本号 |
| `updatedAt` | 更新时间 |
| `status` | 草稿、启用、停用 |

## 安全方案

API Key 只能存放在 `.env` 中，通过服务端读取。前端不得出现 Coze API Key 或任何敏感配置。部署到 Vercel 时，环境变量通过平台配置，不提交到代码仓库。

首版安全措施包括：

| 领域 | 方案 |
|---|---|
| 密钥保护 | `.env`、`.env.example`、服务端调用 |
| 请求限流 | 按 IP 或会话对 AI 接口限流 |
| 参数校验 | Zod 校验用户输入长度、类型和必填项 |
| 异常处理 | API 统一错误码和前端错误状态 |
| 日志脱敏 | 不记录手机号、学号、身份证号等敏感信息 |
| 内容边界 | 对内部系统和个人隐私查询触发拒答 |

## 部署方案

首版部署到 Vercel。部署流程应保持简单：连接 Git 仓库，配置环境变量，构建并发布。为了比赛稳定演示，应准备线上地址和本地演示两套方案。

部署前需要检查：环境变量是否配置、AI 接口是否可用、知识库是否存在启用条目、错误页是否正常、移动端布局是否可用、深色模式是否无明显异常。

## 架构取舍

不建议首版引入数据库、完整账号系统、复杂 CMS 或自动爬虫。原因是比赛周期内这些能力会增加开发和调试成本，且不直接提升核心演示效果。更合适的方式是用文件化知识库和轻量后台完成资料维护，等首版稳定后再扩展数据库和权限系统。

## 阶段一结论

曲智通的架构应先保证“可部署、可演示、可维护、可信回答”。技术难点集中在 AI Workflow 和知识库质量，而不是页面数量或后端复杂度。后续开发应优先完成首页、AI 聊天页、知识库检索、结构化回答和拒答机制。
